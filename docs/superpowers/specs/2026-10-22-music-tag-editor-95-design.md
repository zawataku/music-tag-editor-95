# 音楽タグエディタ 95 — 設計書

- 作成日: 2026-10-22
- リポジトリ: `music-tag-editor-95`
- 参考実装: `../exif-viewer-95`（外観・プロセス構成・ビルド設定を踏襲）

## 1. 目的

Sony Music Center / iTunes の「プロパティ」相当の編集機能（アーティスト名・アルバム名・アルバムアートワーク等）を、
Windows 9x 風の見た目を持つ Electron デスクトップアプリとして提供する。

ライブラリ管理アプリではなく **フォルダ型のタグエディタ** とする。
ファイル/フォルダを開く → 一覧から選ぶ → プロパティを編集 → 保存、が唯一のワークフロー。

### 成功基準

1. MP3 / M4A / FLAC / OGG のタグを読み込み、一覧に表示できる。
2. 単一・複数選択のいずれでも標準項目とアートワークを編集・保存できる。
3. 保存後に他アプリ（エクスプローラー、iTunes/Music Center 等）で同じ値が見える。
4. 書き込み中に失敗しても元ファイルが壊れない。
5. 見た目が exif-viewer-95 と同系統の Win98 スタイルで統一されている。

### 非スコープ（v1）

- 再生・試聴、ライブラリDB、プレイリスト
- オンライン取得（MusicBrainz / iTunes 検索など）。通信は一切しない
- WAV / AIFF
- 歌詞・読み仮名（ソート用フィールド）・BPM・生フレーム編集
- 1ファイル内の2枚目以降の画像の編集（保持のみ）
- フォルダツリー表示、ファイル名リネーム

## 2. 対応形式と編集項目

| 形式 | 拡張子 | タグ方式 |
|---|---|---|
| MP3 | `.mp3` | ID3v2（v2.3 で書き込み。既存 v2.4 はそのまま維持） |
| M4A / AAC | `.m4a`, `.m4b`, `.mp4`(音声) | iTunes (MP4 `ilst`) |
| FLAC | `.flac` | Vorbis Comment + PICTURE ブロック |
| OGG | `.ogg`, `.oga`, `.opus` | Vorbis Comment（画像は METADATA_BLOCK_PICTURE） |

編集項目（標準セット）:

| キー | 表示名 | 型 |
|---|---|---|
| `title` | タイトル | string |
| `artist` | アーティスト | string（複数値は `; ` 区切りで表示・入力） |
| `album` | アルバム | string |
| `albumArtist` | アルバムアーティスト | string（同上） |
| `composer` | 作曲者 | string（同上） |
| `genre` | ジャンル | string（同上） |
| `year` | 年 | 0〜9999 の整数。0 = 未設定 |
| `track` / `trackCount` | トラック番号 n / 総数 | 整数。0 = 未設定 |
| `disc` / `discCount` | ディスク番号 n / 総数 | 整数。0 = 未設定 |
| `comment` | コメント | string（複数行） |
| `artwork` | アートワーク | 表紙画像1枚（JPEG / PNG） |

## 3. 技術スタック

- Electron 43 系（exif-viewer-95 と同一）
- タグ読み書き: **`node-taglib-sharp`**（純 JS/TS。ネイティブビルド不要）
- 画像の寸法取得: レンダラーで `<img>` の `naturalWidth/Height`（追加ライブラリなし）
- ビルド: `electron-builder`（Windows: NSIS + portable、x64）
- テスト: Node 組み込みの `node --test`

### 4.1 共通クローム

exif-viewer-95 から流用する:

- フレームレスウィンドウ + HTML 製タイトルバー（`-webkit-app-region: drag`）
- HTML 製メニューバー（`Menu.setApplicationMenu(null)`）
- `style.css` のトークン（`--face` 等）、ベベル（`.out` `.in` `.thin-in` `.thin-out`）、スクロールバー、ボタン
- `force-device-scale-factor=1`（ビットマップフォント対策）
- CSP: `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' blob: data:; connect-src 'none'`

### 4.2 左ペイン: ファイル一覧

- 列: `#`（トラック番号）、タイトル、アーティスト、アルバム、年、形式、ファイル名。
- 列ヘッダークリックで昇順/降順ソート。初期順はフォルダ順 → ディスク → トラック → ファイル名。
- 単一クリック / Ctrl+クリック / Shift+クリック / Ctrl+A で選択。
- 未保存の変更があるファイルの行は **太字**。保存に失敗したファイルの行は赤字にし、ツールチップにエラー文言。
- ファイル/フォルダのドラッグ&ドロップで一覧に追加（既存一覧に追記。重複パスは無視）。
- 仮想スクロールは v1 では行わない（数千件で重くなるのは既知の制限）。

### 4.3 右ペイン: タブ付きプロパティ

右ペイン上部に Win98 プロパティシート風のタブ「**詳細**」「**アートワーク**」を置く。
選択中タブはタブ帯から1段せり出し、パネル枠と繋がる描画にする。
キーボード: Ctrl+Tab / Ctrl+Shift+Tab でタブ切替。選択タブは一覧の選択が変わっても維持する。

何も選択されていないときは両タブの入力をすべて無効化（灰色）する。

#### 詳細タブ

ラベル + テキストボックスの縦並び（Win98 の `.in` 枠付き入力）。

```
タイトル(T)          [______________________]
アーティスト(R)      [______________________]
アルバム(L)          [______________________]
アルバムアーティスト  [______________________]
作曲者(C)            [______________________]
ジャンル(G)          [______________________]
年(Y) [____]   トラック [__] / [__]   ディスク [__] / [__]
コメント(M)
[__________________________________________]
[__________________________________________]
```

- 数値欄は数字以外を受け付けない。空欄 = 0（未設定）。
- 複数選択時、ファイル間で値が異なる欄は空欄 + 灰色のプレースホルダー「(複数の値)」。
  その欄に入力した時点で「変更あり」となり、保存時に選択中の全ファイルへその値を書く。
  一度も触れなかった欄はどのファイルにも書かない。
- 欄を空にして確定した場合は「その項目を削除する」という変更として扱う。

#### アートワークタブ

```
アルバム アートワーク(A)
┌──────────────────────────────┐
│                              │
│      画像（中央・縦横比維持）     │
│                              │
└──────────────────────────────┘
500 x 500 ピクセル / JPEG / 84 KB
[アートワークを追加(D)…]   [削除(R)]  [書き出し(E)…]
```

- 画像は `.in` ベベルの枠内に `object-fit: contain` で **上下左右中央** に表示し、ペインサイズに追従して拡縮する（拡大はしない: 元画像より大きくは描かない）。
- アートワークがない場合は枠中央に灰色文字「アートワークがありません」。
- 画像下に「幅 x 高さ ピクセル / 形式 / 容量」。
- 「アートワークを追加…」は左下に配置。追加手段は次の3つ:
  1. ボタン → 画像ファイル選択ダイアログ（`.jpg .jpeg .png`）
  2. 枠への画像ファイルのドラッグ&ドロップ
  3. アートワークタブ表示中の Ctrl+V（クリップボードの画像。PNG として扱う）
- 「削除」は表紙画像を削除する変更。「書き出し…」は現在表示中の画像を保存ダイアログで書き出す（拡張子は MIME から決定）。
- 複数選択時:
  - 全ファイルのアートワークのバイト列が一致 → それを表示。
  - 一致しない → 枠中央に「(複数のアートワーク)」。書き出しは無効。
  - 追加/削除すると選択中の全ファイルに適用される変更になる。
- 1ファイルに複数画像がある場合、表紙（`FrontCover`。無ければ先頭）のみを表示・置換・削除の対象にし、その他の画像は保持する。
- JPEG / PNG 以外の画像は追加時にエラーダイアログで拒否する。サイズ上限は設けないが 10 MB を超える場合は確認ダイアログを出す。


exif-viewer-95 と異なり、ブラウザ単体動作（`window.desktop` 無しのフォールバック）は **持たない**。
`node-taglib-sharp` が Node 専用のため。

### 5.1 `main/tags.js` のインターフェース

```js
// 一覧表示用。画像本体は含めない。
read(path) -> Promise<{
  path, format: 'MP3'|'M4A'|'FLAC'|'OGG',
  title, artist, album, albumArtist, composer, genre, comment,  // string ('' = 未設定)
  year, track, trackCount, disc, discCount,                     // number (0 = 未設定)
  artwork: { mime, size, hash } | null                          // hash = SHA-1(bytes)
}>

// アートワーク本体。選択時にのみ取得する。
readArtwork(path) -> Promise<{ mime, data: Uint8Array } | null>

// patch に含まれるキーだけを書き換える。
// patch.artwork: { mime, data } で置換、null で削除、キー無しで不変。
write(path, patch) -> Promise<ReadResult>   // 書き込み後に read() し直した結果を返す
```

- 複数値フィールド（artist 等）は taglib-sharp の配列 ⇔ `; ` 区切り文字列で相互変換する。
- 書き込みは taglib-sharp の共通 `Tag` API（`title`, `performers`, `albumArtists`, `composers`, `genres`, `year`, `track`, `trackCount`, `disc`, `discCount`, `comment`, `pictures`）のみを使い、形式固有 API には触れない。
- MP3 は ID3v2.3 で保存する設定にする（Windows エクスプローラー互換性のため）。

### 5.2 安全な書き込み

taglib-sharp はファイルをその場で書き換えるため、`write()` は次の手順で行う:

1. 同じディレクトリに `.<name>.mte-tmp` としてコピー（同一ボリュームで rename を原子的にするため）。
2. 一時ファイルに対して taglib-sharp で書き込み・`save()`・`dispose()`。
3. 一時ファイルを `read()` し直して期待値と一致するか検証。
4. `fs.rename` で元ファイルを置き換える。元ファイルのタイムスタンプ（mtime）は書き込み後の時刻になる（保持しない）。
5. いずれかで失敗したら一時ファイルを削除し、元ファイルには触れずにエラーを返す。

### 5.3 IPC（`window.desktop`）

| メソッド | 内容 |
|---|---|
| `minimize / maximize / close / isMaximized / onMaximizeChange` | exif-viewer-95 と同じ |
| `openFiles()` / `openFolder()` | ダイアログ → パス配列（キャンセル時 `null`） |
| `expand(paths)` | ドロップされたパス群を対象ファイル一覧に展開（最大深さ 8、最大 20000 件） |
| `pathForFile(file)` | `webUtils.getPathForFile` |
| `readTags(path)` / `readArtwork(path)` / `writeTags(path, patch)` | `main/tags.js` に委譲 |
| `pickImage()` | 画像選択ダイアログ → `{ mime, data }` |
| `saveImage({ mime, data }, suggestedName)` | 保存ダイアログで書き出し |
| `reveal(path)` | `shell.showItemInFolder` |
| `confirmClose()` / `onCloseRequest(cb)` | 未保存時の終了確認（下記） |

アートワークの `data` は IPC 上 `Uint8Array` で受け渡す（構造化クローンで転送。Base64 にしない）。
レンダラー側では `Blob` → `URL.createObjectURL` で表示し、不要になったら `revokeObjectURL` する。

## 6. レンダラーの状態とデータフロー

```
files: Map<path, { tags: ReadResult, patch: Partial<Tags>, status: 'ok'|'saving'|'error', error? }>
order: path[]           // 現在のソート順
selection: Set<path>
activeTab: 'detail' | 'artwork'
```

- **読み込み**: 開く/ドロップ → `expand` → 各パスを並列度 4 で `readTags` → 到着順に一覧へ追加。読めないファイルはエラー行として表示し編集不可。
- **表示値の算出**: 選択ファイルそれぞれについて `{...tags, ...patch}` を作り、項目ごとに全員一致なら値、不一致なら「(複数の値)」。
- **編集**: 入力欄の `input` イベントで、選択中の全ファイルの `patch[key]` に値を入れる。`patch` が元の `tags` と同値になったキーは削除する（＝未保存表示が消える）。
- **元に戻す**: 選択中ファイルの `patch` を空にする。
- **保存**: `patch` が空でないファイルを 1 件ずつ順に `writeTags`。成功したら `tags` を戻り値で更新し `patch` を空に。失敗したら `patch` を残し行を赤字にする。全件終了後、失敗があれば件数とファイル名をまとめてダイアログ表示。
- **終了確認**: ウィンドウの `close` をメインで `preventDefault` し、レンダラーに問い合わせる。未保存があれば「変更を保存しますか？ [はい][いいえ][キャンセル]」の Win98 風ダイアログ（HTML 製）。
- **一覧の置き換え**（開く/フォルダを開く）時も、未保存があれば同じ確認を出す。

## 7. エラー処理

| 状況 | 挙動 |
|---|---|
| 非対応・破損ファイル | 一覧にエラー行（灰色、形式欄に「エラー」）。選択しても編集欄は無効 |
| 読み取り専用・ロック中ファイルの保存 | 当該行を赤字、まとめダイアログで報告。他ファイルの保存は続行 |
| 書き込み後の検証不一致 | 置き換えせず失敗扱い |
| 非対応画像形式の追加 | エラーダイアログ「JPEG または PNG を指定してください」 |
| フォルダ走査が上限到達 | ステータスバーに「上限 20000 件で打ち切りました」 |

ダイアログはすべて HTML 製の Win98 風モーダル（ネイティブの `dialog.showMessageBox` は使わない。ファイル選択/保存ダイアログのみネイティブ）。

## 8. テスト

## 10. 既知の制限（README に記載する）

- 仮想スクロール無しのため、数千件で一覧描画が重くなる。
- 表紙以外の画像は編集できない（保持のみ）。
- 歌詞・読み仮名・BPM などは編集できず、既存の値は保持される。
- 保存するとファイルの更新日時が変わる。
